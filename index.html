Success criteria

Two headline deliverables

Everything else in this workshop (SharePoint ingestion, MCP server, guardrails, governance) exists to support these two outcomes, not as separate parallel goals.

1

A working RAG retrieval flow

HNE's existing Azure AI Search index registered as a Foundry Knowledge Source, queried with hybrid search, answering real questions with citations, not a synthetic demo dataset.

2

A live Hosted Agent demo

That same knowledge source wired into a Hosted Agent (Preview) a real client can talk to directly through a minimal chat web app, not just a notebook script.

Structure

Eight numbered modules: problem, exercise, outcome

00 · Day 0

Prereqs

Day 1 stalls at 10:00 if the environment isn't ready: subscription access, model deployments, and the search index all need confirming beforehand.

Problem · Exercise · Outcome
Exercise
  • Confirm subscription access, roles, and the Foundry policy exception
  • Verify the existing Azure AI Search index is reachable
  • Confirm every participant can sign in locally
Outcome

Verification checklist fully checked off before Monday, so no morning is lost to environment troubleshooting.

01 · Track A

Platform setup

Track B can't build anything until Foundry is provisioned with an identity it can authenticate with.

Problem · Exercise · Outcome
Exercise
  • Provision the resource group and starting footprint
  • Create a user-assigned Managed Identity for the Foundry project
  • Grant Search Index Data Reader + Cognitive Services OpenAI User roles
Outcome

Foundry project endpoint reachable, Managed Identity has both role assignments, Track B connects successfully.

02 · Track B · Headline #1

RAG knowledge source

HNE's existing search index needs to answer real questions with citations, not just return raw search hits.

Problem · Exercise · Outcome
Exercise
  • Connect to the Foundry project and inspect the index schema
  • Compare lexical vs. vector vs. hybrid search on real questions
  • Register the index as a managed Foundry IQ Knowledge Base
Outcome

A real question returns a synthesized, cited answer, not just search hits, and the Knowledge Base's MCP endpoint is ready for Tuesday's agent.

03 · Track B · Headline #2

Hosted Agent demo

A retrieval flow that only runs in a script isn't something a real client can talk to.

Problem · Exercise · Outcome
Exercise
  • Deploy the retrieval flow as a Hosted Agent (Preview)
  • Wire in the Knowledge Base and the MCP server as tools
  • Re-run the same test questions through the agent
Outcome

A Hosted Agent answers real questions with citations, the MCP server is callable as a tool, and any preview issues are written down, not just discussed.

04 · Track A

SharePoint ingestion

HNE currently hand-feeds content into the index, so ingestion needs to be automatic and permission-aware.

Problem · Exercise · Outcome
Exercise
  • Register a read-only service principal for the indexer
  • Map SharePoint permissions/ACLs into the index
  • Agree a dev/test/prod split and the Copilot-licence question
Outcome

At least one real SharePoint document is indexed and returns a working citation through the Hosted Agent.

05

MCP server

HNE explicitly asked for MCP best practices and hosting guidance, not just a theoretical explanation.

Problem · Exercise · Outcome
Exercise
  • Run the example MCP server locally over stdio
  • Test the streamable-HTTP transport Foundry actually needs
  • Deploy it so Foundry can reach it as a remote tool
Outcome

The MCP server runs as a deployed, callable tool the Hosted Agent can use for business actions beyond search.

06

Custom web app

HNE wanted to see a full custom web app, not just an agent inside the Foundry Playground.

Problem · Exercise · Outcome
Exercise
  • Run the FastAPI + HTML/JS chat UI locally against the Hosted Agent
  • Confirm a question round-trips with a citation link
  • Time permitting, containerize and deploy it
Outcome

A real question round-trips through the web app with a working citation, as a repeatable deploy, not a one-off script.

07 · Joint session

Governance

None of this is sustainable without agreed ownership for platform, model, data, cost, and guardrails.

Problem · Exercise · Outcome
Exercise
  • Work through five checklists together, live, in one room
  • Assign an owner to each open item on the spot
  • Feed unresolved items into the roadmap
Outcome

Agreed decisions on provisioning ownership, model approval, data/permissions, cost, and the guardrails pipeline.
